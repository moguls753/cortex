Where it runs

Three ways to run it.

What changes is who does the work, who is liable, and who notices when it breaks.

All on your machine

One compose file brings up Postgres, Whisper, Ollama and the app. It wants a real box: a NUC, an old desktop, something with roughly 8 GB free, because the embedding model on its own is about 4.7 GB.

A Raspberry Pi will run the application quite happily. It will not run the transcription.

Your machine, heavy parts on APIs you pick

The same install and the same code. Transcription and the language model go to a provider you choose, on your key and your account. That takes the memory floor away, which puts the whole thing back within reach of a Pi.

You pick the company, you read their terms, you can move on a Tuesday afternoon if you stop liking them.

Your contract, not mine.

My machine

No install, no server, no updates, no compose file to keep half an eye on. You tap an invite link and start talking to the bot.

The board is served from my box, and your panel fetches it exactly as it would fetch one from yours.

What is being sold in the third one is not “hosting”. Hosting is a word for renting a computer, and a computer can be rented anywhere.

I transcribe, I sort, and I notice when it breaks.

The first two are the parts thin hardware cannot do. The third one is not hardware at all, and it is the one that decides whether the thing is still working in March.

Honest status

Echo Show has done voice at the wall for years, at €329. Nobody should pretend otherwise and I am not going to start.

The difference here is narrow, so I would rather state it narrowly: a free-form spoken thought instead of a list command, something that actually structures it afterwards, the processing on a machine you chose, and the result on E-Ink instead of a backlit screen. That is the whole claim. There is no wider one.

Accuracy is structurally unmeasurable.

There is no ground truth for “was that understood the way it was meant”. A free-form spoken sentence has no single correct structuring, so there is nothing to score against, no benchmark exists, and I have not built one because I am not yet convinced one can be built honestly. Which means there is no accuracy figure anywhere on this page, and there will not be one until there is a real number to put there.

What it does

  • Takes text and voice messages in one Telegram chat.
  • Sends the recording through Telegram, then transcribes it wherever you chose.
  • Turns what you said into dated entries and reminders.
  • Renders the board server side, and your panel fetches the image.
  • Writes the morning briefing and sends it as an email.

Where it gets things wrong

  • Dates read off a loose phrase. “The week after next” lands on the wrong Tuesday often enough that you will see it happen.
  • One sentence carrying two jobs sometimes arrives as one entry, and the second job quietly disappears into the first.
  • When it does that, you say so in the same chat and it changes. Everything on the board is editable, nothing is buried, and the panel redraws on its next fetch.
  • The briefing goes out by mail. A mail server that has quietly stopped sending looks exactly like a morning with nothing to report.
  • No testimonials, no case studies, no benchmarks. Nothing on this page is a customer speaking.
  • The name is not spellable from hearing it. Anyone told “cortex board” out loud will type cortexboard. Links absorb that, conversations will not.

The stack

For whoever reads the source before they believe the page.

What it listens to

The Telegram Bot API. A typed message or a voice message, no separate app to install and nothing new to learn. A voice message is fetched back down from Telegram’s servers in src/telegram.ts, and transcribed after that, wherever you chose.

What structures it

A language model, local or over an API. Embeddings run on qwen3-embedding at 4096 dimensions, which is where most of the 8 GB goes. There is also an MCP server and semantic search across what you have said. Both exist, neither is the argument for this thing, which is why they are down here.

What it draws

Satori to resvg, server side, in src/display/render.ts. Out comes a 4-bit greyscale PNG at whatever size the panel asks for. The panel speaks BYOS and simply fetches the image.
